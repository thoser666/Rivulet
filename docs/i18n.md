# Internationalization (i18n)

Rivulet's UI is fully driven by locale translation tables. Every user-visible
string goes through `Locale::tr()` or `Locale::tr_fmt()`, so no text is
hard-coded in the GUI. The default locale is English; German is the second
built-in language.

## Architecture

| Layer | Location | Role |
|---|---|---|
| Key table | `rivulet-core/src/i18n.rs` | `Locale::En` and `Locale::De` static tables with 479 key/value pairs each |
| Tr helpers | `Locale::tr(key)`, `Locale::tr_fmt(key, &args)` | Borrow-based lookup; falls back to the key itself when a translation is missing |
| App integration | `rivulet-gui/src/app.rs` — `self.tr(key)` / `self.tr_fmt(key, &args)` | Wraps `self.locale.tr(key)` so every widget uses the currently selected locale |
| Locale selector | Settings → Language menu | Persists the choice via `eframe`; restored on next launch |
| OS auto-detect | `detect_os_locale()` in `app.rs` | On first launch (no persisted state), reads `LC_MESSAGES` / `LANG` env vars |

## Key naming convention

Keys are `snake_case` and grouped by feature area:

- `recording_*` — recording controls and status
- `stream_*` — streaming controls and status
- `scenes_*` — scene management
- `filter_*` — audio/video filters
- `chat_*` — Twitch/Kick/YouTube chat
- `midi_*` — MIDI mapping
- `hotkey_*` — hotkey settings
- `nav_*` — sidebar navigation labels

Placeholders use positional `{0}`, `{1}`, … syntax:

```rust
Locale::En.tr_fmt("recording_in_progress", &[seconds.to_string()]);
// → "Recording in progress (42s)"
```

## Adding a new locale

1. Add a variant to the `Locale` enum in `rivulet-core/src/i18n.rs`:

```rust
pub enum Locale {
    En,
    De,
    Fr, // ← new
}
```

2. Add it to `Locale::all()`, `from_code()`, `code()`, and `name()`.
3. Add a `Locale::Fr => &[...]` table in `strings()` with **every** key from
   the EN table (the parity test enforces this).
4. Add the locale to the `Locale::all()` array so it appears in the Settings
   language picker.

## Adding a new key

1. Add the key + English value to the `Locale::En` table.
2. Add the same key + German value to the `Locale::De` table.
3. Use `self.tr("new_key")` in the GUI widget.
4. The `all_keys_present_in_all_locales` test ensures no key is missing in
   any locale — adding a key to EN but not DE (or vice-versa) will fail CI.

## Parity test

`i18n::tests::all_keys_present_in_all_locales` iterates every key in EN and
asserts it exists in DE, and vice-versa. This catches drift automatically:
if a developer adds a translation to only one locale, the test fails.

A second guard in `rivulet-core/tests/ci_pinning.rs` reads `i18n.rs` from
disk and counts keys in both tables, failing if the counts differ.

## OS locale detection

On first launch (no persisted settings), `detect_os_locale()` checks:

1. `LC_MESSAGES` environment variable (Linux/macOS standard)
2. `LANG` environment variable (set by most Linux distros and Git Bash on Windows)

If neither is set, the default is English. The user can always override via
Settings → Language, which persists across restarts.
